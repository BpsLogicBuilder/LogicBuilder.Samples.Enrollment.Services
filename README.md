A sample enterprise application demonstrating server-side workflow execution using business rules generated by [BPS Logic Builder](https://github.com/BlaiseD/LogicBuilder). This repository showcases a clean architecture approach for building rule-driven enrollment management services with .NET.

## Overview

This solution implements an enrollment management system where business logic is defined visually using BPS Logic Builder and executed through a rules engine. The architecture separates concerns across multiple layers, enabling maintainable and testable enterprise applications.

## Architecture

The solution follows a layered architecture pattern with clear separation of concerns:

### API Layer

- **Enrollment.Api** - RESTful API service that serves as the entry point for client applications
  - Communicates with the BSL service using certificate-based authentication
  - Handles CORS policies and JSON serialization
  - Integrates with Azure Key Vault for certificate management
  - Targets: .NET 10

### Business Services Layer (BSL)

- **Enrollment.Bsl** - Business Services Layer host application
  - Exposes workflow operations via REST API controllers
  - Uses certificate-based authentication for secure service-to-service communication
  - Orchestrates the execution of business rules and workflows
  - Integrates dependency injection, AutoMapper, and Entity Framework
  - Targets: .NET 10

- **Enrollment.Bsl.Flow** - Workflow execution engine
  - Contains the workflow **RuleSets** generated by BPS Logic Builder (stored in the `Rulesets/` folder)
  - Each ruleset includes `.module` and `.resources` files for operations like:
    - Validation workflows (validateacademic, validateadmissions, validatecertification, etc.)
    - Save workflows (saveacademic, saveadmissions, savepersonal, etc.)
    - Delete workflows (deleteacademic, deleteuser, etc.)
  - Implements the flow activity factory for workflow execution
  - Targets: .NET 10

- **Enrollment.BSL.AutoMapperProfiles** - Object mapping configuration
  - Defines AutoMapper profiles for transforming between domain models and data entities
  - Targets: .NET 10

### Business Layer

- **Enrollment.Domain** - Domain models and business entities
  - Contains domain models (AcademicModel, UserModel, etc.) decorated with LogicBuilder attributes
  - Defines the core business entities used throughout the application
  - Targets: .NET Standard 2.0 (for maximum compatibility)

- **Enrollment.Repositories** - Repository pattern implementation
  - Provides abstraction over data access operations
  - Implements the repository pattern for domain entities
  - Targets: .NET 10

### Data Access Layer (EF)

- **Enrollment.Data** - Data entity definitions
  - Defines Entity Framework data entities and contracts
  - Uses LogicBuilder.Data abstractions
  - Targets: .NET Standard 2.0

- **Enrollment.Contexts** - Entity Framework database contexts
  - Configures SQL Server database contexts
  - Manages database connections and configurations
  - Targets: .NET 10

- **Enrollment.Stores** - Data access implementations
  - Implements concrete data stores using Entity Framework Core
  - Provides CRUD operations against the database
  - Targets: .NET 10

### Testing

- **Enrollment.Api.Tests** - Integration tests for the API layer
- **Enrollment.Bsl.Flow.Tests** - Tests for workflow execution
- **Enrollment.Bsl.Tests** - Tests for the Business Services Layer

## Key Technologies

## BPS Logic Builder Integration

The core feature of this solution is its integration with BPS Logic Builder:

1. **Visual Rule Design**: Business rules and workflows are designed visually using the Logic Builder designer
2. **Code Generation**: The designer generates `.module` and `.resources` files stored in `Enrollment.Bsl.Flow/Rulesets/`
3. **Runtime Execution**: The BSL Flow engine executes these rules at runtime based on incoming requests
4. **Separation of Logic**: Business logic is externalized from code, allowing non-developers to modify rules

## Getting Started

### Prerequisites

- .NET 10 SDK
- SQL Server (local or Azure)
- Visual Studio 2026 or later (recommended)
- Azure subscription (for Key Vault and certificate management)

### Configuration

Configure the following settings in your `appsettings.json` or user secrets:

- Database connection string
- Azure Key Vault URL
- BSL certificate name
- Allowed CORS origins

### Running the Application

1. Set up the database using Entity Framework migrations
2. Configure Azure Key Vault with required certificates
3. Run the `Enrollment.Bsl` service
4. Run the `Enrollment.Api` service
5. Access the API endpoints for enrollment operations
